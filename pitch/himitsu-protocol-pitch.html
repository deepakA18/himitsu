Hhimitsu01 · The gap

THE PROBLEM

A public wallet swap can link a user to a trade.

A standard wallet swap publishes the sender, amount, and time.

Those public details can connect a wallet to its later activity.

A private note can hide which pool deposit is spent, but it needs proof-based authorization to trade through an AMM.

The product problem is to authorize the note, execute a limited swap, and place the output in a new note.

THE SOLUTION

Himitsu swaps from a private note through Uniswap V2.

The browser proves ownership. The pool checks the allowed action. The AMM executes the swap. A second pool records the output as a new private note.

Hhimitsu04 · Transaction design

WHY THE CURRENT FLOW DOES NOT USE ERC-4337

Himitsu submits a native EIP-8141 transaction.

0x06

EIP-8141 TRANSACTION TYPE

ERC-4337 sends a UserOperation through an EntryPoint contract and a bundler. Himitsu does not create UserOperations or use that route.

The current design needs the shared pool to be the transaction sender, prove the note spend, and authorize a separate gas payer. EIP-8141 represents those steps as ordered frames in one transaction.

This is an architecture choice for an EIP-8141-compatible Ethrex network. ERC-4337 can also support sponsored accounts, but it uses a different transaction path.

Sources: EIP-4337 · EIP-8141 draft

Hhimitsu05 · What is different

EIP-8141 IS THE TRANSACTION CORE

One type-0x06 transaction runs four ordered frames.

01 · VERIFYEXPIRY

Check deadline

The 0x8141 verifier rejects an expired transaction.

02 · VERIFYPOOL

Prove note spend

The pool checks the proof, nullifier, and allowed action.

03 · VERIFYPAYMASTER

Approve gas payment

The paymaster checks its policy and fee limits.

04 · SENDERPOOL

Execute the swap

The pool calls Uniswap V2 and deposits output into the next pool.

The pool is the transaction sender. The separately funded paymaster pays network gas. The user’s wallet does not pay gas for the swap.

WHAT THE PROOF HIDES, AND WHAT IT DOES NOT

The proof hides the spent note, not the public swap.

Private

The proof shows that the user controls a valid, unspent note without naming its deposit commitment. The note secret and witness stay in the browser.

Hhimitsu09 · Current status

WHAT EXISTS TODAY

The application implements the full note-to-note flow.

Implemented

The browser creates notes and Groth16 proofs. The pool validates spends. A paymaster applies gas limits. The frame transaction swaps through Uniswap V2 and creates an output note.

The repository includes integration flows for deposits, swaps, withdrawals, and failed swaps.

Not yet established

EIP-8141 is still a draft. The current deployment uses a pinned Ethrex implementation. The contracts and circuits need independent security review.

Public-network compatibility, throughput, sponsor operations, and privacy under real user activity remain to be evaluated.
